# Руководство по соавторству и публикации контента на сайте

Данный документ содержит технические правила, требования к разметке и пошаговый алгоритм для авторов, желающих принять участие в развитии разделов Творческой лаборатории.


### Алгоритм отправки изменений (Workflow)

1. **Создание форка:** Сделайте официальный форк репозитория сайта `eaststandart.github.io` через интерфейс GitHub.
2. **Локальная ветка:** Создайте новую рабочую Git-ветку внутри своего форка (например, `patch-fix-article`).
3. **Внесение правок:** Добавьте статью, исправьте опечатку или оптимизируйте макет, строго следуя техническим правилам проекта.
4. **Запрос на слияние:** Опубликуйте ветку у себя и откройте *Pull Request* в ветку `main` оригинального репозитория Лаборатории.

### Технические правила для авторов контента

#### 1. Стандартизация метаданных страниц (Jekyll Front Matter)
Каждый новый текстовый документ в папках разделов (например, `diary/`, `projects/`, `tools/`) обязан начинаться со строгого блока метаданных YAML, расположенного между тройными дефисами `---`.
* В блоке параметров должны быть явно определены поля: `layout:` (шаблон разметки), `title:` (заголовок страницы), `description:` (краткое описание контента) и служебный параметр `module:`, указывающий на имя текущего файла. Все строки заполняются на понятном русском языке без кавычек.

#### 2. Правила оформления графики и медиафайлов
* **Формат и сжатие:** Все новые фотографии детских поделок, схем или чертежей перед добавлением должны быть сконвертированы в современный оптимизированный формат `WebP`. Это критически важно для сокращения времени загрузки страниц сайта.
* **Разметка:** Для вставки изображений внутри статей рекомендуется использовать канонический HTML-тег `<figure>` (или системный шорткод `fig`) с обязательным указанием поясняющей подписи к рисунку.

#### 3. Языковые стандарты и стиль
* Все статьи, комментарии к инженерным проектам, описания коммитов и новые разделы руководств ведутся строго на грамотном, доступном русском языке. 
* Проект ориентирован на юных техников, поэтому избегайте перегружения текстов сложным профессиональным ИТ-жаргоном. Объясняйте сложные инженерные термины простыми и понятными словами.
