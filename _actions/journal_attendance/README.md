## 📅 Подсистема генерации отчетов и Телеграм-оповещений

В данном каталоге сосредоточена серверная Python-логика обработки сданных преподавателями журналов, публикации итоговых таблиц на сайте и рассылки уведомлений.

### Структура папки

```text
[eaststandart.github.io]
└── _actions/ 
    └── journal_attendance/ 
        ├── ja_data_parser.py        # Модуль сетевого парсинга и сборщика отчетов
        ├── ja_gate_closer.py        # Модуль шлюзового обновления данных и очистки
        ├── ja_report_builder.py     # Модуль маркдаун-дизайна и GraphQL-публикации отчётов
        ├── ja_tgbot_notify.py       # Модуль отправки отчетов в каналы и группы Телеграм
        ├── ja_tgbot_personal.py     # Модуль отправки персональных отчетов в Телеграм
        └── journal_attendance.py    # Модуль управления сборкой отчета посещений
```

### Архитектура конвейера обработки

Все скрипты вызываются последовательно через единый управляющий модуль. Движение данных организовано в 4 этапа:

```text
[journal_attendance.py] (Диспетчер)
       │
       ├──► 1. [ja_data_parser.py]   (Сбор сырых JSON из сети и чтение базы YAML)
       ├──► 2. [ja_report_builder.py] (Проверка комплектности, сборка таблиц и GraphQL-публикация)
       ├──► 3. [Телеграм-рассылка] ──► [ja_tgbot_personal.py] (Личные отчеты по ID)
       │                             └── [ja_tgbot_notify.py]   (Анонсы в каналы/чаты)
       │
       └──► 4. [ja_gate_closer.py]   (Обновление YAML базы и REST-очистка шлюза)
```

### Спецификация модулей подсистемы

*   **`journal_attendance.py` (Модуль управления сборкой отчета посещений)**
    *   **Назначение:** Координация работы модулей генерации отчетов и рассылки уведомлений в Телеграм.
    *   **Логика работы:** Инициализирует запуск строителя отчетов. При успешном получении пакетов считывает персональные настройки чатов преподавателей напрямую из их YAML-конфигураций и поочередно передает управление модулям личных и публичных рассылок, а в финале запускает шлюзовой закрыватель конвейера.

*   **`ja_data_parser.py` (Модуль сетевого парсинга и сборщика отчетов)**
    *   **Назначение:** Загрузка JSON, YAML и транзит плоских структур для генератора отчетов.
    *   **Логика работы:** Через запросы к GitHub API собирает список active преподавателей, выкачивает прилетевшие JSON-файлы групп из папки `_output` и оригинальные файлы расписания YAML. Преобразует данные в плоские списки и упаковывает всё в изолированные именные пакеты.

*   **`ja_report_builder.py` (Модуль маркдаун-дизайна и GraphQL-публикации отчётов)**
    *   **Назначение:** Импорт сырых данных из парсера, контроль комплектности учебного дня, сборка таблиц и отправка в Discussions.
    *   **Логика работы:** Жестко проверяет комплектность (сданы ли все запланированные на день группы). Сканирует GraphQL-запросом комментарии в указанных GitHub Discussions для поиска поделок по тегам учащихся. Генерирует Маркдаун-код итоговой таблицы и отправляет её мутацией GraphQL в целевую ветку обсуждений сайта.

*   **`ja_tgbot_personal.py` (Модуль отправки персональных отчетов в Телеграм)**
    *   **Назначение:** Формирование сжатого текста журнала и отправка личных уведомлений в Телеграм.
    *   **Логика работы:** Построчно сжимает Маркдаун-таблицу до компактного текстового формата, заменяет длинные статусы на короткие эмодзи (`🟢`, `🟡`, `🔵`), автоматически сокращает дни недели и рассылает сообщения по списку `tg_personal_id` из настроек.

*   **`ja_tgbot_notify.py` (Модуль отправки отчетов в каналы и группы Телеграм)**
    *   **Назначение:** Рассылка уведомлений по каналам и чатам Телеграм со ссылкой на журнал посещений.
    *   **Логика работы:** Формирует красивую HTML-карточку анонса с невидимой ссылкой на публикацию. Построчно разбирает конфигурацию каналов и вложенных в них веток (топиков). Умеет распознавать флаг главной ветки (`g`), исключая её идентификатор из запроса, и отправляет данные методом `sendMessage`.

*   **`ja_gate_closer.py` (Модуль шлюзового обновления данных и очистки)**
    *   **Назначение:** Сетевое обновление YAML базы расписания и удаление отработанных JSON.
    *   **Логика работы:** Импортирует обновленный состав учащихся из памяти Python. Построчно читает оригинальный YAML-файл, находит целевой день и время группы, проводит алфавитную сортировку имен и **только при наличии реальных изменений** PUT-запросом обновляет базу на GitHub с сохранением комментариев. После этого выполняет REST-удаление отработанных JSON-файлов из папки `_output` приватного репозитория.
