# [Сайт] Добавить чат сайта с двусторонней связью через Telegram
## Цель

Реализовать на сайте Лаборатории простой канал личного общения с посетителями, родителями, детьми и участниками проектов.

Это не полноценный мессенджер и не замена GitHub Discussions. Задача — дать возможность задать индивидуальный вопрос или обсудить рабочий момент, а автору сайта — отвечать из Telegram.

## Основной сценарий

- На сайте размещён компактный чат.
- Посетитель отправляет сообщение через сайт.
- Сообщение поступает автору в Telegram.
- Автор отвечает на него непосредственно в Telegram.
- Ответ возвращается в соответствующий диалог на сайте.
- Для каждого собеседника сохраняется отдельная история переписки, чтобы диалоги не смешивались.

## Категории собеседников и доступ

Предусмотреть общение с:
- обычными посетителями сайта;
- родителями;
- детьми и участниками инженерных проектов.

Возможны открытый режим для посетителей и личный режим с индивидуальным кодом или ссылкой для родителей и участников. Конкретную модель доступа определить при проектировании.

## Принципы реализации

- Минимальный и понятный интерфейс.
- Двусторонняя доставка сообщений между сайтом и Telegram.
- Раздельные диалоги и история переписки.
- Защита личных сообщений и серверное хранение данных.
- Защита от спама и несанкционированного доступа.
- Без функций полноценного мессенджера: групповых чатов, сложных статусов, контактов и т. п.

## Примеры существующих решений

Изучить перед проектированием:
- [Intergram](https://github.com/idoco/intergram) — простой виджет сайта, сообщения посетителей поступают в Telegram, ответы отправляются обратно.
- [Supportgram](https://github.com/Sorbh/supportgram) — виджет с отдельными диалогами в Telegram Topics, историей и возвратом ответов на сайт.
- [Kaplia Chat](https://github.com/vitaliikaplia/kaplia-chat) — более крупная самостоятельная система чата с сервером, панелью управления и интеграцией Telegram.

## Когда выполнять

Вернуться к задаче после завершения текущей работы над Конструктором комментариев.

Сначала сравнить примеры и выбрать подходящую архитектуру. Не переносить в проект избыточные функции готовых систем.
