## JavaScript-модули Конструктора комментариев

В этом каталоге находится клиентская логика Конструктора комментариев. Скрипты написаны на JavaScript и разделены по функциональным задачам. Разделение упрощает сопровождение проекта: каждый модуль отвечает за свою часть интерфейса или процесса сохранения.

### Структура папки

```text
assets/
└── js/
    └── comment-builder/
        ├── 01-comment-notify.js       # Уведомления и статусы операций
        ├── 02-comment-auth.js         # Авторизация и проверка доступа преподавателя
        ├── 03-comment-form.js         # Инициализация, состояние и сброс формы
        ├── 04-drafts-parser.js        # Разбор Markdown и Front Matter черновиков
        ├── 05-drafts-loader.js        # Получение списка черновиков из GitHub
        ├── 06-drafts-injector.js      # Восстановление выбранного черновика в форме
        ├── 07-drafts-delete.js        # Управление удалением черновиков
        ├── 08-comment-validation.js   # Проверка даты, текста и данных формы
        ├── 09-comment-lock.js         # Блокировка формы на время операций
        ├── 10-media-blocks.js         # Создание и удаление фото- и видеоблоков
        ├── 11-media-files.js          # Данные, выбор и подготовка медиафайлов
        ├── 12-media-files-ui.js       # Интерфейс списка файлов и действия с ними
        ├── 13-media-upload.js         # Загрузка медиафайлов в GitHub
        ├── 14-comment-markdown.js     # Формирование и кодирование Markdown
        ├── 15-comment-github-save.js  # Создание и обновление Markdown-файлов
        └── 16-comment-submit.js       # Общий процесс отправки и сохранения
```

### Подключение модулей

Все 16 файлов подключаются в `_includes/comment-builder.liquid` в указанном выше порядке.

Порядок подключения важен: модули используют функции и общие переменные, объявленные в других файлах. При этом нумерация отражает порядок загрузки скриптов, а не строгую последовательность выполнения всех операций. Функции запускаются по событиям интерфейса и в ходе соответствующих сценариев работы.

### Назначение модулей

**01-comment-notify.js — уведомления и статусы**
- Показывает пользователю уведомления об успешных операциях, ошибках и текущем состоянии.
- Управляет доступностью кнопки выхода во время выполняемых операций.

**02-comment-auth.js — авторизация**
- Проверяет GitHub-токен и права пользователя.
- Проверяет, входит ли преподаватель в список разрешённых пользователей.
- Сохраняет токен и логин преподавателя в `localStorage`.
- Запускает инициализацию конструктора после успешной проверки доступа.

**03-comment-form.js — форма конструктора**
- Инициализирует интерфейс конструктора.
- Управляет состоянием и значениями полей формы.
- Выполняет сброс формы.

**04-drafts-parser.js — разбор черновиков**
- Разбирает Front Matter и Markdown-содержимое черновика.
- Извлекает данные комментария, фото- и видеоблоков, а также сведения о прикреплённых файлах.

**05-drafts-loader.js — загрузка списка черновиков**
- Получает список файлов из каталога `_input/` репозитория `techlab-comment-builder`.
- Обрабатывает ответы GitHub API и подготавливает список доступных черновиков.

**06-drafts-injector.js — восстановление черновика**
- Заполняет форму данными выбранного черновика.
- Восстанавливает медиаблоки, сведения о файлах и ссылки на них.
- Настраивает связанные с восстановленным черновиком элементы формы.

**07-drafts-delete.js — удаление черновика**
- Создаёт и обслуживает элемент управления удалением черновика.
- Управляет состоянием удаления и учитывает его при сохранении.

**08-comment-validation.js — проверка данных**
- Проверяет корректность календарной даты.
- Проверяет обязательные и необязательные поля комментария.
- Проверяет данные медиаблоков перед сохранением.
- Возвращает сообщение об ошибке, если данные необходимо исправить.

**09-comment-lock.js — блокировка формы**
- Блокирует и разблокирует элементы формы на время операций.
- Управляет завершением операции и восстановлением состояния интерфейса.

**10-media-blocks.js — медиаблоки**
- Создаёт и удаляет блоки фотографий и видео.
- Обновляет доступность элементов управления медиаблоками.

**11-media-files.js — данные медиафайлов**
- Обрабатывает выбор файлов и их регистрацию в медиаблоках.
- Проверяет типы и дубликаты файлов.
- Подготавливает имена и данные файлов для дальнейшей загрузки.

**12-media-files-ui.js — интерфейс медиафайлов**
- Отображает список файлов внутри медиаблоков.
- Обрабатывает удаление, замену, выбор и перетаскивание файлов.
- Отображает состояние файлов, в том числе отсутствующих или требующих замены.

**13-media-upload.js — загрузка медиафайлов**
- Подготавливает локальные файлы к загрузке.
- Загружает файлы в каталог `_input/` репозитория `techlab-comment-builder` через GitHub Contents API.
- Обрабатывает результаты загрузки и ошибки.

**14-comment-markdown.js — формирование Markdown**
- Собирает данные формы и медиаблоков.
- Формирует Markdown-документ с Front Matter.
- Кодирует и декодирует содержимое в формате Base64 с поддержкой UTF-8.
- Формирует ссылки и подписи медиафайлов, включая файлы, добавленные через WikiLink.

**15-comment-github-save.js — сохранение Markdown**
- Создаёт новые и обновляет существующие Markdown-файлы в `_input/`.
- Проверяет актуальную версию файла перед обновлением.
- Обрабатывает конфликт версий и повторяет попытки при временных сетевых ошибках.

**16-comment-submit.js — отправка и сохранение**
- Координирует полный процесс сохранения комментария или черновика.
- Перед сохранением проверяет дату, номер обсуждения и данные формы.
- Запускает подготовку Markdown и загрузку медиафайлов.
- Обрабатывает режимы сохранения, публикации и удаления черновика.
- Показывает итоговый статус операции.

### Основные рабочие процессы

#### Авторизация и запуск
1. Преподаватель вводит GitHub-токен или использует ранее сохранённый токен.
2. Конструктор проверяет токен и логин пользователя.
3. После подтверждения доступа инициализируется интерфейс.

#### Загрузка и редактирование черновика
1. Конструктор получает список черновиков из `_input/`.
2. Парсер разбирает выбранный Markdown-файл.
3. Модуль восстановления заполняет поля формы и восстанавливает медиаблоки.
4. Преподаватель может изменить данные и сохранить черновик повторно.

#### Сохранение комментария или черновика
1. Проверяются дата, номер обсуждения и содержимое формы.
2. Формируется Markdown-файл с Front Matter.
3. Markdown сохраняется в `_input/` репозитория `techlab-comment-builder`.
4. Новые медиафайлы загружаются в тот же каталог.
5. При успешной загрузке медиафайлов Markdown обновляется, чтобы зафиксировать окончательный комплект данных.
6. Конструктор сообщает результат операции.

### Репозиторий и данные

- **Репозиторий:** `eaststandart/techlab-comment-builder`.
- **Рабочий каталог:** `_input/`.
- **Назначение репозитория:** буферное хранение Markdown-комментариев, черновиков и связанных медиафайлов для последующей обработки.
- **Авторизация:** GitHub Personal Access Token преподавателя.
- **Ключ токена в браузере:** `github_comment_token`.
- **Логин преподавателя в браузере:** `github_comment_logged_user`.

### Правила сопровождения

- При добавлении или удалении модуля обновлять список файлов в этом README и порядок подключения в `_includes/comment-builder.liquid`.
- Сохранять нумерацию и соответствие имени файла его назначению.
- При изменении ответственности модуля актуализировать его описание здесь и заголовок `@about` / `@purpose` в самом JavaScript-файле.
- Не переносить функции между модулями и не менять их поведение только ради документации.
- README описывает фактическую реализацию; при изменении кода документацию следует проверять и обновлять.
