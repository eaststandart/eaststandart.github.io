## Клиентские скрипты управления Журналом посещаемости

В данном каталоге сосредоточена изолированная клиентская логика веб-страницы Журнала. Все скрипты написаны на чистом JavaScript (JS) без тяжелых внешних зависимостей для обеспечения максимальной скорости загрузки и работы интерфейса.

### Структура папки

```text
[eaststandart.github.io]
└── assets/
    └── js/ 
        └── journal-attendance/ 
            ├── 01-core-auth.js            # Настройки и авторизация. 
            ├── 02-students-loader.js      # Загрузка расписания. 
            ├── 03-yaml-parser.js          # Разбор и проверка YAML. 
            ├── 04-journal-ui.js           # Отображение дней и групп. 
            ├── 05-attendance-commands.js  # Посещаемость и команды. 
            ├── 06-status-and-repair.js    # Статусы и ремонт. 
            └── 07-validation.js           # Проверка входных данных.  
```

### Контур сквозной цепочки скриптов

Файлы пронумерованы и работают в жесткой последовательной цепочке. Движение процессов разделено на два потока:

```text
       [01-core-auth.js] ──────────► Авторизация и запуск идентификации токена
              │
              ▼
       [02-students-loader.js] ────► Сканирование сети и загрузка YAML-расписания
              │
              ▼
       [03-yaml-parser.js] ────────► Парсинг YAML, контроль отступов и валидация
              │
              ▼
       [04-journal-ui.js] ─────────► Отрисовка календаря, групп и полей отметки
              │
              ▼
 ┌────────────┴────────────┐
 │                         │
[ПОТОК А: Штатный режим]  [ПОТОК Б: Режим системных команд ремонта расписания]
 │                         │
 ▼                         ▼
[05-attendance-commands.js][05-attendance-commands.js] (Сборка JSON /d, /r, /m)
(Сбор отметки учеников)    │
 │                         ▼
 ▼                        [06-status-and-repair.js] ──► (Взвод сигналов, циклическая
[05-attendance-commands.js]                             проверка и опрос статусов)
(PUT-отправка в _input/)   │
                           ▼
                          [07-validation.js] ─────────► (Контроль кавычек и спецсимволов)
```

### Спецификация скриптов фронтенда

*   **`01-core-auth.js` (Модуль авторизации и контроля доступа)**
    *   **Назначение:** Управление сессией входа, валидация ключей доступа и базовая инициализация интерфейса.
    *   **Логика работы:** Выполняет автоматический вход при наличии токена в `localStorage`. При ручном вводе отправляет тестовый запрос к API GitHub для проверки прав, сохраняет логин преподавателя в кэш браузера и запускает контур сквозной идентификации пользователя.

*   **`02-students-loader.js` (Модуль сетевой загрузки базы расписания)**
    *   **Назначение:** Выкачивание файлов личного расписания преподавателей из приватного репозитория данных.
    *   **Логика работы:** Генерирует сетевой URL-запрос к файлу `journal-attendance-[логин].yml` с динамическим ключом против кэширования. Декодирует полученный Base64-код в текстовую строку и передает её парсеру. На основе успешного ответа разблокирует только те кнопки дней недели под календарем, которые физически существуют в расписании.

*   **`03-yaml-parser.js` (Модуль объектного парсинга и валидации синтаксиса)**
    *   **Назначение:** Преобразование сырого текста YAML в структурированный JavaScript-объект с одновременным поиском дефектов структуры.
    *   **Логика работы:** Построчно сканирует файл расписания. Игнорирует комментарии и секцию настроек `config:`. Включает жесткие фильтры геометрических отступов (0 пробелов для дней, 2 для времени, 4 для учеников, 6 для параметров) и математический контроль реальности времени суток (от 00:00 до 23:59). При обнаружении малейшего брака останавливает сборку и вызывает аварийный блок.

*   **`04-journal-ui.js` (Модуль динамической отрисовки интерфейса)**
    *   **Назначение:** Генерация интерактивных элементов управления, календарной сетки, чекбоксов учащихся и полей ввода на веб-странице.
    *   **Логика работы:** Сбрасывает CSS-подсветку кнопок и выводит общую карточку даты занятий. Парсит списки учеников, зряче отсекая для экрана служебные теги и скобки. Формирует карточки групп с инлайновыми текстовыми полями для ввода новичков и временных учеников, снабжая каждую группу индивидуальной кнопкой сохранения.

*   **`05-attendance-commands.js` (Модуль сбора посещаемости и обработки системных команд)**
    *   **Назначение:** Формирование JSON-пакетов от отметок присутствия или сборка директив изменения базы данных.
    *   **Логика работы:** Проверяет поле ввода новичков на наличие ключевого слова `journal` и управляющих флагов (`/d` — удаление, `/r` — ремонт, `/m` — время). Если команда найдена, блокирует интерфейс красным баннером перестройки расписания и передает пакет в Поток Б. В штатном режиме собирает чекбоксы присутствующих, прогоняет строки новичков через Whitelist-регулярки букв (запрещая голые теги и ввод цифр), запрашивает SHA существующего файла на сервере для исключения конфликтов и отправляет PUT-запрос в папку `_input/`.

*   **`06-status-and-repair.js` (Модуль управления состояниями и опроса сервера)**
    *   **Назначение:** Вывод системных статус-баров, блокирующих аварийных баннеров и отправка универсальных сигналов ремонта.
    *   **Логика работы:** Управляет отображением всплывающих уведомлений и кнопки выхода из профиля. Отвечает за отправку JSON-файлов сигналов на сервер и запускает непрерывный 5-секундный цикл опроса (polling) файла `repair-status-[логин].json`. При возврате сервером статуса `"off"` перезапускает загрузку чистого расписания, а при статусе `"error"` выводит на экран преподавателя «живой лог» ошибки из Python.

*   **`07-validation.js` (Модуль контроля безопасности строк)**
    *   **Назначение:** Защита текстовых полей ввода от ломающих структуру спецсимволов.
    *   **Логика работы:** Выступает в роли изолированного щита безопасности. Проверяет строки на баланс кавычек (запрещая непарные знаки) и сканирует текст на наличие запрещенных символов (таких как квадратные скобки, обратные слэши, знаки точки с запятой или равенства), исключая инъекции некорректного кода в базу данных.
